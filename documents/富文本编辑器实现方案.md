# 富文本编辑器实现方案

## Context（背景）

从零构建基于 **React + ProseMirror** 的富文本编辑器，配套 **Node.js + Express** 后端。核心诉求：

1. React 搭建界面（工具栏、色盘、插入模块），编辑器本身基于 ProseMirror。
2. **模块化架构**：普通文本、图片、视频、音频、列表、表格等每种能力各自封装成独立模块（独立目录/文件），由主模块（注册中心）统一注册，可灵活增删、可被外部扩展（宿主也能注册自定义模块）。
3. 编辑器是可集成的独立 package，可注册外部事件。
4. `/` 唤起插入菜单，支持直接输入或搜索选择。
5. AI 内容摘要、长文本虚拟滚动、内容导入导出；媒体资源以 id 存储、异步加载、支持虚拟滚动。

因当前无 `AskUserQuestion` 工具，以下为按用户既有规则与最常见实践确定的默认决策，可在审批时纠正：

- **虚拟滚动方案**：媒体/资源块级虚拟化（IntersectionObserver 懒加载占位）+ 顶层内容 `content-visibility: auto` CSS 加速；长文本由 PM 原生渲染（瓶颈在重媒体而非纯文本）。
- **AI 摘要**：可配置 OpenAI 兼容接口（`OPENAI_BASE_URL`/`OPENAI_API_KEY`/`OPENAI_MODEL`），无 fallback（符合规则 7）。
- **后端持久化**：文档存 JSON 文件，媒体存本地 `uploads` 目录。
- **单仓结构**：pnpm workspace，editor 作为独立可发布 package。

## 技术选型

- 前端：React 18 + TypeScript + Vite（app 演示）+ Ant Design + @ant-design/icons。
- 编辑器核心（`packages/editor`）：直接使用 ProseMirror 系列包：
  `prosemirror-state`、`prosemirror-view`、`prosemirror-model`、`prosemirror-schema-basic`、`prosemirror-schema-list`、`prosemirror-commands`、`prosemirror-keymap`、`prosemirror-history`、`prosemirror-inputrules`、`prosemirror-gapcursor`、`prosemirror-tables`（表格）。不用 TipTap，保持对 PM 的完全掌控。
- editor 包构建：`tsup`（产出 ESM + CJS + .d.ts，可发布）。
- 后端：Node.js + Express + multer + TypeScript（`tsx` 运行）。

## 关键设计

### 1. 模块化架构（Module Registry，核心诉求）

每个能力就是一个 `EditorModule`，由主模块 `modules/index.ts` 统一注册，合并为最终的 Schema / 命令 / 插件 / 工具栏 / 菜单 / NodeView。

**`modules/types.ts` 定义模块契约：**

```ts
export interface EditorModule {
  name: string
  nodes?: Record<string, NodeSpec>
  marks?: Record<string, MarkSpec>
  plugins?: Plugin[]
  commands?: Record<string, Command>
  keymaps?: Record<string, Command>
  inputRules?: InputRule[]
  nodeViews?: Record<string, NodeViewFactory>
  toolbarItems?: ToolbarItemConfig[]   // { id, label, type, command, render? }
  slashItems?: SlashItemConfig[]       // { id, title, keywords?, icon?, command, group? }
}
```

**主模块 `modules/index.ts`：**

```ts
export const builtinModules: EditorModule[] = [
  textModule, headingModule, listModule, blockquoteModule, codeBlockModule,
  linkModule, colorModule, imageModule, videoModule, audioModule,
  tableModule, historyModule, gapcursorModule, aiSummaryModule,
]
```

**`manager/registry.ts` 负责合并：**

- `buildSchema(modules)`：合并所有 `nodes`/`marks`，注入必有的 `doc`/`text` 节点，生成单一 Schema。
- `collectCommands(modules)` / `collectPlugins(modules)` / `collectKeymaps(modules)` / `collectInputRules(modules)` / `collectNodeViews(modules)` / `collectToolbarItems(modules)` / `collectSlashItems(modules)`：聚合各模块能力。

要点：
- 每个模块目录自包含（schema/commands/toolbar/slash/nodeview 都在各自目录），删除一个模块即可整体移除该能力。
- 模块间无交叉依赖，只通过 registry 聚合，避免耦合。

### 2. 编辑器作为可集成 package + 扩展机制（需求 3）

`<RichEditor/>` 对外暴露 props：

- `doc?`（初始文档 JSON）、`onChange(doc)`、`onReady(view)`、`initialHTML?`。
- `resourceResolver?: (resourceId: string) => Promise<{ url: string; mime: string }>` — 媒体异步加载注入点。
- `modules?: EditorModule[]` — 宿主追加自定义模块（与内置模块合并）。
- `plugins?: Plugin[]`、`slashItems?`、`toolbarItems?`。

`EditorManager`（实例由 `onReady` 返回，也可 Headless 创建）：

- `manager.registerModule(module)` / `registerModules([...])`
- `manager.on('update' | 'selectionChange' | 'focus' | 'blur' | 自定义事件, handler)`
- `manager.emit(event, payload)`
- `manager.addToolbarItem(config)` / `manager.addSlashItem(config)`
- `manager.commands.*`（聚合后的命令）

`index.ts` 同时导出 `createEditor`、`EditorManager`、`builtinModules`、`types`、`serialization`，支持 headless 使用。

### 3. Schema 与文档格式（PM JSON 为唯一事实来源）

- 基础节点由 `text` 模块提供：`doc`、`paragraph`、`text`、`hardBreak`。
- 基础 marks 由 `text` 模块提供：`strong`、`em`、`underline`、`strike`、`code`。
- 各模块贡献各自节点/mark：`heading`、`bullet_list`/`ordered_list`/`list_item`、`blockquote`、`code_block`、`link(href/title)`、`textColor(color)`、`backgroundColor(color)`、`table` 系列、`imageResource`/`videoResource`/`audioResource`。

媒体节点 attrs 仅存元数据，二进制通过 `resourceId` 后端异步解析（契合需求 7）：

```json
{ "type": "imageResource", "attrs": { "resourceId": "rk-xxx", "mime": "image/png", "alt": "", "width": null, "height": null } }
```

### 4. 工具栏 + 色盘 + 插入模块（需求 2，React 实现）

`Toolbar.tsx`（antd）聚合各模块 `toolbarItems` 渲染，而非硬编码按钮：

- 文字格式（text/heading/list/blockquote/codeBlock/link）→ 加粗/斜体/下划线/删除线/行内代码/链接、标题下拉、有序无序列表、引用、代码块。
- `color` 模块提供「文字颜色 / 背景高亮」色盘，antd `ColorPicker` 落到 `textColor`/`backgroundColor`。
- 「插入模块」下拉：图片 / 视频 / 语音 / 表格（来自 image/video/audio/table 模块的 slash/toolbar 项），触发文件上传 → 后端返回 `resourceId` → 对应 command 插入。
- 工具栏高亮由选区状态驱动，编辑器选区变化时同步 React state。

### 5. `/` 插入菜单（需求 4）

`slashPlugin`：监听 `/` 输入，弹 `SlashMenu` 弹层（`view.coordsAtPos` 定位）。

- 顶部过滤输入框（继续输入过滤候选），下方是各模块 `slashItems` 聚合后的可选列表（图片、视频、语音、表格、标题 1/2/3、引用、代码块、有序/无序列表、分割线、AI 摘要）。
- 支持 ↑/↓ 导航、Enter 插入、Esc 关闭、点击插入。
- 纯文本类命令直接触发对应 command，媒体类触发上传+插入。

### 6. AI 摘要（需求 5）

- 前端：工具栏「AI 摘要」或 slash 项 → 取 doc 纯文本 → `POST /api/ai/summary` → 在 `AISummaryPanel` 展示。
- 后端 `routes/ai.ts`：读 `OPENAI_BASE_URL`/`OPENAI_API_KEY`/`OPENAI_MODEL`，调 OpenAI 兼容 `/chat/completions`，返回摘要。

### 7. 虚拟滚动与媒体异步加载（需求 6/7）

- **媒体虚拟化**：`MediaNodeView.tsx` 渲染固定尺寸占位（图片宽 200px 高自适应；视频 16:9；音频为固定高播放条），`IntersectionObserver` 进入视口后才调 `resourceResolver(resourceId)` 加载真实资源，移出视口卸载省内存。
- **长文本**：PM 原生渲染文本 + 内容容器 `content-visibility: auto; contain-intrinsic-size: auto 400px` 做 CSS 级离屏块跳过布局。
- 后端 `GET /api/resources/:id`（元数据）+ `GET /api/resources/:id/file`（二进制）支撑异步加载。

### 8. 导入导出（需求 7）

- `serialization.ts` 提供 `toJSON` / `toHTML` / `toMarkdown` 及 `fromJSON`/`fromHTML`。
- 工具栏/App 提供「导出 JSON / HTML / Markdown」（`Blob` 下载）与「导入文件」。
- 导入 JSON 中媒体仅 `resourceId`，导入后由 `resourceResolver` 异步解析占位。

### 9. 后端 API（需求 8）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/documents/:id` | 获取文档 JSON |
| PUT | `/api/documents/:id` | 保存文档 JSON |
| POST | `/api/resources` | 上传媒体（multer），返回 `{ resourceId, mime, url }` |
| GET | `/api/resources/:id` | 资源元数据 |
| GET | `/api/resources/:id/file` | 返回二进制文件 |
| POST | `/api/ai/summary` | AI 摘要 |

存储：`store.ts` 用 `fs` 读写 `data/documents/`；上传落 `uploads/{resourceId}.{ext}`。

## 实施步骤

1. 初始化 pnpm workspace（根 `package.json`、`pnpm-workspace.yaml`、`tsconfig`）。
2. 搭建 `packages/editor` 骨架：`modules/types.ts`、`manager/registry.ts`、`manager/EditorManager.ts`、`core/createView.ts`、`RichEditor.tsx`、`index.ts`。
3. 实现各模块（先基础后媒体/表格/颜色/链接/AI 摘要），每个模块自包含 schema/commands/toolbar/slash。
4. 实现工具栏、色盘、slash 菜单、选区状态插件。
5. 实现媒体 NodeView（占位 + IntersectionObserver 懒加载 + resourceResolver）。
6. 实现序列化（JSON/HTML/Markdown）。
7. 搭建 `server`：Express + 路由 + store + multer 上传 + AI 摘要。
8. 搭建 `packages/app`：集成编辑器、resourceResolver 对接后端、导入导出按钮。
9. 联调验证。

## 验证方式

1. 后端：`cd server && pnpm dev`（`tsx watch src/index.ts`），确认接口可用。
2. 前端：`cd packages/app && pnpm dev`（Vite）。
3. 端到端：
   - `/` 唤起菜单，可过滤并插入标题/列表/表格/图片/视频/语音。
   - 上传图片后文档出现占位，滚动到视口后经后端加载真实图片；长文档滚动时离屏媒体不加载。
   - 工具栏加粗/改色/标题/列表/表格生效，色盘改文字颜色。
   - 删除某模块目录并在 `modules/index.ts` 取消注册后，对应能力整体消失（验证模块化可插拔）。
   - 生成 AI 摘要（需配置 OpenAI 兼容 env）。
   - 导出 JSON/HTML/Markdown，再导入 JSON 可还原内容与媒体占位。
   - 刷新页面从后端拉取文档 JSON 正常渲染。
